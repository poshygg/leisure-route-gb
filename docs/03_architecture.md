| | 문제 | 성격 | 난이도 |
|---|---|---|---|

## B. 경로 탐색

```
cost(e) = length(e) / (1 + λ · A(e))          A(e) = Σ wᵢ · scoreᵢ(e) ∈ [0,1]
```

**왜 뺄셈이 아니라 나눗셈인가** — `length·(1-λA)` 는 음수가 될 수 있고
Dijkstra는 음수 가중치에서 깨집니다. 나눗셈은 항상 양수이고 해석도 자연스럽습니다:
`A=1, λ=1` → *"이 길 1m는 0.5m처럼 느껴진다."*

### 우회 예산

사용자는 3배 돌아가길 원하지 않습니다. `L(route) ≤ β·L₀` 제약을 걸어야 하는데
이건 **Constrained Shortest Path = NP-hard**입니다.

**해법: λ 격자 스윕** (이분 탐색 아님 — 근거는 [04_decisions.md](04_decisions.md) ADR-002)

```
λ ∈ linspace(0, 8, 24) 각각에 대해 Dijkstra
  → 길이 ≤ β·L₀ 인 것 중 amenity 최대 선택
Dijkstra 24회 = 수백 ms. 최단/균형/여유 3옵션도 같은 스윕에서 공짜.
```

**UX** — λ를 노출하지 말고 3버튼: 최단 `β=1.0` / 균형 `β=1.25` / 여유 `β=1.6`

### 구현

```python
def route(src, dst, w, beta=1.25, lam_grid=np.linspace(0, 8, 24)):
    p0 = _path(src, dst, L)
    L0 = L[p0].sum()
    A  = np.clip(PHI @ w, 0, 1)

    best, best_a = p0, 0.0
    for lam in lam_grid:
        p = _path(src, dst, L / (1.0 + lam * A))
        if L[p].sum() <= beta * L0:
            a = (L[p] @ A[p]) / L[p].sum()      # 길이가중 평균
            if a > best_a:
                best, best_a = p, a
    return best, L0
```

> **핵심 판단** — 속성 점수 자체는 규칙으로 계산하고, **"합치는 가중치"만 학습합니다.**

> 반면 **"A 경로 vs B 경로 중 어느 게 더 여유로운가"** 는 사람이 1초에 답합니다.
> 그래서 학습 형태는 **pairwise ranking**이어야 합니다.

## C. 학습 — 라벨 0개에서 시작

### 두루누비 GPX 284코스 = 공짜 전문가 라벨

한국관광공사가 "걷기 좋은 길"로 인증한 **실제 폴리라인 284개**가 있습니다.

```
Positive: 전문가 코스 P
Negative: 같은 시종점(OD)의 최단경로 Q      ← 전문가가 "일부러 피한" 길
```

같은 출발·도착인데 전문가는 P를 골랐고 최단은 Q입니다.
**contrastive learning의 완벽한 셋업**이고 284쌍이 자동 생성됩니다.

```python
def route_score(epath, w):
    l = L[epath]
    return (l @ (PHI[epath] @ w)) / l.sum()      # 길이 정규화 필수

def loss(w):
    w = np.abs(w); w /= w.sum()                  # w≥0, Σw=1 (식별성)
    d = np.array([route_score(P[i], w) - route_score(Q[i], w) for i in range(N)])
    return np.maximum(0, MARGIN - d).mean()      # margin ranking
```

**파라미터 10개, 샘플 284개** → scipy로 충분합니다. PyTorch 불필요, 오버피팅 걱정 거의 없음.

Positive 추가 확보: 전국길관광정보표준데이터의 유적탐방길·둘레길, 가로수길 표준데이터, 무장애나눔길.

### 맵매칭

GPX를 우리 그래프 엣지열로 바꿔야 합니다.

- **Valhalla `trace_attributes`** — GPX → `edge.way_id` → OSM way id로 조인. **여기서만 엔진 사용.**
- 자체 매처도 가능: `GPX 포인트 → 20m 내 최근접 엣지 → 중복 제거 → 끊긴 구간 최단경로 연결`.
  284개면 이걸로 충분합니다.

### 다음 단계 (데이터 쌓인 뒤)

**Maximum Entropy IRL** (Ziebart, 2008) — "전문가 경로를 보고 보상함수를 역추정".
원 논문 실험이 **택시 경로 예측**이라 도메인이 그대로 맞습니다.
선형 모델의 한계가 보일 때 넘어가세요. **MVP에는 과합니다.**

### 개인화 (나중)

```
w_user = w_global + Δ_user      # Δ는 강한 정규화, 소수 샘플로 학습
```
온보딩에서 A/B 경로 3~5쌍 선택을 받아 초기화. 콜드스타트 유저는 `w_global`.

## ⚠️ 속성 상관 — 설계에 직접 영향

**중복 (강한 양의 상관)**
- **강변 → 조용 + 하늘 + 나무 + 발편함(둔치는 평지)** 을 동시에 만족
  → **강변 하나만 잘 해도 4~5개가 따라옵니다. MVP 1순위 확정.**
- 꽃길 ⊂ 나무 많은 길 (둘 다 가로수가 소스)

**직접 충돌**
- 나무 많음 ↔ 하늘 잘 보임 (수관이 하늘을 가림)
- 문화재·볼거리 ↔ 조용함 (관광지는 시끄러움)
- 발 편함 ↔ 전망 (전망 좋은 길은 대개 오르막)

→ **슬라이더 10개는 UX 실패가 확정입니다.**
엣지 × 10속성 행렬에 상관 클러스터링/PCA를 돌려 축을 축약하세요. 예상:

```
축1  초록·물    : 나무, 꽃, 강변
축2  볼거리     : 문화재, 오브제, 벽화·특화거리, 건물
축3  쾌적·편안  : 조용, 발편함, 하늘
```
축2 ↔ 축3이 충돌하므로 사용자에겐 **삼각 슬라이더 하나**가 맞습니다.

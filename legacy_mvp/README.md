# 낭만 경로 탐색기 (romantic_route)

"꽃 보면서 조용히 걷고 싶어" 같은 한 문장으로, **좋은 것들을 지나는 도보 경로**를 찾는다.
경상북도를 1차 대상으로 만든 MVP.

---

## 설계의 핵심 세 가지

### 1. 회피가 아니라 선호 — 그런데 알고리즘은 같다

"나쁜 걸 피하는" 라우팅은 그냥 Dijkstra다. "좋은 걸 지나는" 라우팅은 순진하게 짜면
Orienteering Problem(= Prize-Collecting Path)이 되고 **NP-hard**다.

이 프로젝트는 후자를 전자로 되돌린다. 좋은 것에 **할인을 주지 않고**, 좋지 않은 곳에
**페널티를 준다**:

```
deficit(e) = Σ wᵢ · (1 − scoreᵢ(e))          # ∈ [0,1]
cost(e)    = length(e) · (1 + strength · deficit(e))
```

`deficit ≥ 0` 이므로 **`cost(e) ≥ length(e)` 가 항상 성립**한다.
이게 왜 중요하냐면, 배수를 1 아래로 내리는 순간(= 할인) 직선거리 휴리스틱이
실제 남은 비용을 과대추정하게 되어 **A\* 가 최적해를 놓친다**. 부호를 뒤집는 것만으로
탐색 알고리즘 전체가 그대로 살아있다. (`verify_gb.py` 가 이 불변식을 검사한다)

### 2. 데이터가 없으면 축을 끈다 — 조용히 틀린 답을 내지 않는다

경북에서 제일 중요한 부분이다. 두 겹의 게이트가 있다.

| 게이트 | 판정 | 동작 |
|---|---|---|
| 계절 | `flower` 는 3~7·9~10월만 | 철 아니면 제외 + "다음 9월" 안내 |
| 데이터 | 점수 ≥ 0.3 인 간선이 3% 미만 | 제외 + 사유 출력 |
| 조회 | Overpass 실패 | `FetchError` 로 구분 (0건과 절대 안 뭉갬) |

제외된 축의 가중치는 남은 축에 **재분배**된다. 축이 하나도 안 남으면 경로를 내지 않고
왜 못 내는지 말한다.

> 초기 버전은 조회 실패를 `except: return empty` 로 삼켰다. 그 결과 "이 동네엔 문화재가
> 없다"와 "서버가 죽었다"가 같은 결과가 되어, 라우팅이 조용히 최단경로와 같은 답을 냈다.

### 3. 점수는 그 지역 분포로 재스케일한다

절대 기준(예: 100m당 12그루 = 만점)을 쓰면 안 된다. OSM 가로수 태깅 밀도는 지역 간
10배 이상 차이 나서, 서울 기준을 포항에 적용하면 전 구간이 0점 근처로 뭉개지고
**비용이 균일해져 최단경로와 같은 답이 나온다(라우팅 무력화)**.

`adaptive_rescale()` 이 그 지역 비영(非零) 값의 85퍼센타일을 만점으로 잡아 다시 편다.

## 왜 Overpass 가 아니라 로컬 PBF 인가

경북 23개 시군을 라이브 Overpass 로 훑는 건 불가능하다 — 요청 수천 건에 IP 레이트리밋에
걸린다 (실측: `overpass-api.de`, `kumi.systems` 둘 다 100초 이상 타임아웃).

대신 [Geofabrik 한국 전체 추출본](https://download.geofabrik.de/asia/south-korea-latest.osm.pbf)
(약 273MB)을 한 번 받아 로컬에서 읽는다.

- **2패스 방식**: 노드는 자기 좌표를 들고 있으므로, 패스 A 에서 bbox 안 노드만 좌표표로
  모으고 패스 B 에서 way 를 조립한다. `flex_mem` 전역 위치 인덱스(수 GB)를 피하려는 것.
- **디스크 캐시**: 첫 추출 약 3분, 이후 즉시. (`data/extract_cache/`)
- Overpass 경로도 남아 있다(`--pbf` 생략). 서울 등 소규모 실험용.

## 축 (9개)

| key | 이름 | 출처 | 비고 |
|---|---|---|---|
| `flower` | 꽃 | OSM 수목·정원 | 계절 게이트. **산림청 가로수(86.9만건, 수종명)로 교체 시 정확해짐** |
| `trees` | 나무 그늘 | OSM 수목·숲·공원 | 산림청 흉고직경(DBH)이 있으면 수관피복률로 승급 |
| `heritage` | 문화재 | OSM `historic` | 국가유산청 공간정보(WMS/WFS)로 교체 가능. **경북이 전국 최다** |
| `art` | 벽화·공공미술 | OSM `tourism=artwork` | 전국공공미술및조형물정보표준데이터로 보강 |
| `water` | 물가 | OSM 하천·수역 | 전국하천표준데이터로 교체 가능 |
| `quiet` | 조용함 | OSM `highway` 위계 | 공공 교통량(상시조사 3,920지점)은 이면도로가 없어 **OSM 쪽이 낫다** |
| `skyview` | 트인 하늘 | 건물 점유율 역수 | 근사. VWorld 3D **LoD1 은 전국 구축**이라 승급 가능 |
| `gentle` | 완만함 | DEM 경사 | `--dem` 필요 (국토지리정보원 5m DEM, 전국) |
| `snow` | 설경 | 파생 휴리스틱 | 전용 데이터 없음. trees/water/heritage/skyview 조합임을 명시 |

## 설치

```bash
pip install -r requirements.txt
curl -L -o data/south-korea-latest.osm.pbf \
  https://download.geofabrik.de/asia/south-korea-latest.osm.pbf
```

`pyrosm` 은 Python 3.12 에서 `cykhash` 빌드가 실패한다. 대신 **pyosmium** 을 쓴다.

## 사용

```bash
# 경주 — 문화재 코스
python -m romantic_route.cli --pbf data/south-korea-latest.osm.pbf \
  --from "35.8375,129.2095" --to "35.8340,129.2255" \
  --query "문화재 보면서 나무 많고 조용한 길로"

# 산책(회귀) 모드
python -m romantic_route.cli --pbf data/south-korea-latest.osm.pbf \
  --from "36.0190,129.3435" --loop 40 --query "강변 따라 천천히"

# 버튼 모드 + Claude 자연어 파서
python -m romantic_route.cli --axes heritage quiet water --from ... --to ...
python -m romantic_route.cli --llm --query "봄에 꽃 보러 가기 좋은 한적한 길" --from ... --to ...

python -m romantic_route.cli --list-axes
```

출발/도착은 `lat,lon` 또는 지명(Nominatim 지오코딩). 결과는 콘솔 요약 + `route.html` (folium).

## 자연어 파싱

기본은 사전(lexicon) 기반 — 키 없이 즉시 동작한다. `--llm` 을 주면 Claude
(`claude-opus-5`, effort=low)로 파싱하고 **실패하면 조용히 사전으로 폴백**한다.

사전에는 두 종류가 있다:

- `LEXICON` — 직접 요구 ("꽃", "강변")
- `AVERSION` — **부재가 곧 좋음인 축** ("언덕", "시끄러운"). 여기선 부정 표현이
  요구를 취소하는 게 아니라 **강화**한다. `"언덕은 싫어"` → 완만함 요구.
  일반 부정 규칙을 그대로 적용하면 정반대로 해석된다.

## 경로 재정렬 — 좋은 길은 "좋은 게 많은 길"이 아니다

3km 내내 똑같이 예쁜 벚꽃길보다, 골목 → 하천 → 시장 → 공원으로 바뀌는 3km 가 더 좋다.
점수 총합은 후자가 낮을 수 있는데도.

그런데 이 "변화도"는 **간선 속성이 아니라 경로 전체의 속성**이라 Dijkstra 안에 못 넣는다.
그래서 후보를 k개 뽑아놓고 재정렬한다:

```
score = quality + 0.15 · variety − 0.20 · max(0, detour − 1)
```

`variety` 는 경로 위 간선들의 **지배 축 시퀀스에 대한 Shannon 엔트로피**(0~1 정규화).
후보 생성은 `nx.shortest_simple_paths`(너무 느리다) 대신 **반복 페널티**를 쓴다 —
경로를 찾을 때마다 그 간선 비용을 2배로 올리고 다시 찾는다.

```
  routing.py   비용 합성 · k-경로 · 평가 · 다양성 재정렬

```

## 경북 실측 검증 (`verify_gb.py`)

세 구간에서 strength 를 0→8 로 쓸어 **분위기 가중치가 실제로 경로를 바꾸는지** 확인했다.
축은 `trees / heritage / quiet` 균등.

| 구간 | 간선 | 문화재 | 품질 (str 0 → 2) | 우회 | 최단과 공유 | 판정 |
|---|---|---|---|---|---|---|
| 경주 대릉원~월지 | 6,030 | 137건 | 0.772 → **0.792** | 1.03x | 100% → 83% | 작동 (효과 작음) |
| 포항 시청~죽도시장 | 16,376 | 3건 | 0.262 → **0.505** | 1.02x | 100% → 59% | **작동 (효과 최대)** |
| 안동 하회~병산 | 806 | 8건 | 0.385 → 0.385 | 1.00x | 100% → 100% | **작동 안 함** |

### 읽는 법

**포항에서 효과가 가장 크다.** 직관과 반대인데 이유가 분명하다 — 경주 도심은 최단경로가
이미 대릉원을 관통해서 개선 여지가 없다. 포항은 최단경로가 간선도로를 타므로,
**2% 만 더 걸으면 조용함이 0.45 → 0.86 으로 뛴다.** 좋은 것이 많은 도시가 아니라
*최단경로가 나쁜* 도시에서 이 서비스가 가치를 만든다.

**안동 하회~병산은 어떤 가중치를 줘도 같은 길이 나온다.** 축은 셋 다 `usable` 인데
보행망 간선이 806개뿐이라 **우회로 자체가 존재하지 않는다.** 데이터 게이트로는 못 잡는
실패 유형이라 세 번째 게이트를 추가했다:

```python
routing.diversity_feasible(Gp, orig, dest)   # 최단경로와 98% 이상 겹치면 경고
```

> **경북에서 진짜 병목은 피처 데이터가 아니라 보행망 밀도였다.**
> 문화재·나무 데이터가 부족한 건 게이트로 정직하게 처리되지만, 애초에 길이 하나뿐인
> 농촌 구간에서는 어떤 추천 알고리즘도 할 수 있는 게 없다. 시군 중심부·읍내 단위로
> 대상을 좁히는 게 맞다.

## 알려진 한계

- **`skyview` 는 진짜 SVF 가 아니다** — 반구 적분이 아니라 건물 점유율의 역수 근사다.
- **`snow` 는 데이터가 없다** — 다른 축의 가중합 휴리스틱. 결과를 그렇게 읽어야 한다.
- **OSM 커버리지가 경북에서 고르지 않다** — 그래서 사용가능성 게이트가 있다. 게이트가
  축을 끄면 그건 버그가 아니라 "이 지역엔 그 데이터가 없다"는 정직한 보고다.
- **PBF 추출이 지역당 첫 3분** — 캐시 후엔 즉시. 시군을 미리 다 돌려두면 된다.
- `--dem` 없이는 `gentle` 축이 항상 꺼진다.
